webtuidb keeps what you configure in the config folder and what it remembers in the data folder. Both UIs use the same files, so a terminal UI and a web server can run side by side on one machine. Nothing is sent anywhere.

## Where the folders are

| Folder | Default | With XDG variables |
|---|---|---|
| Config | `~/.config/webtuidb` | `$XDG_CONFIG_HOME/webtuidb` |
| Data | `~/.local/share/webtuidb` | `$XDG_DATA_HOME/webtuidb` |

The XDG variables count only when they are absolute paths. `--config` moves only `config.toml`; everything else stays in these folders. Folders webtuidb creates get mode `0700`, files `0600`. On the first start after the rename from tuidb, `~/.config/tuidb` and `~/.local/share/tuidb` are moved here (see [The config file](../config-file/#migration-from-tuidb)).

## Config folder

| Path | What it is |
|---|---|
| `config.toml` | Your settings. Optional. [The config file](../config-file/), [Settings reference](../settings-reference/). |
| `connections.toml` | Saved connections. [connections.toml](../connections-file/). |
| `themes/` | Installed themes: a folder with a `theme.toml` (from `webtuidb -theme-install`) or a single `<name>.toml`. [Themes](../themes/#installing-themes-from-git). |
| `plugins/` | Plugins: every `*.toml` (a command plugin; `name` and `command` are required) and every `*.js` (a script plugin). A plugin file that does not parse is listed with its error instead of being dropped. See [Plugins](../../automation/). |

## Data folder

### `history/<connection>.jsonl`

The query history: one file per connection, one JSON object per line, oldest first.

| Field | Meaning |
|---|---|
| `id` | A stable id of the entry. |
| `time` | When it ran. |
| `db` | The database it ran in. |
| `sql` | The statement. |
| `dur` | How long it took (nanoseconds). |
| `src` | `editor` (typed in the SQL editor) or `gui` (generated by an edit, commit or other action). |
| `orig` | The previous values of the edited rows, as CSV, when `[general] log_original_values` is on. |

Limits:

- A statement longer than 64 KiB is cut and ends with `-- (truncated)`.
- Each file keeps the newest 5,000 entries. Once a file grows past 16 MiB it is trimmed to the newest entries that fit in half of that.
- A connection name with characters other than letters, digits, `.`, `_` and `-` is percent-encoded in the file name (`Shop (Postgres)` → `Shop%20%28Postgres%29.jsonl`), so `a b` and `a_b` never share a file. Files written by older versions with `_` in place of those characters are renamed on start when exactly one connection matches.

### `queries/`

Saved queries ("favorites"), one plain `.sql` file each. Sub-folders are folders in the saved-queries list. The first lines may carry a name and keywords:

```sql
-- name: Recent orders
-- keywords: ro, recent
SELECT * FROM orders ORDER BY placed_at DESC LIMIT 50;
```

Folders listed in `[queries] shared_dirs` are shown beside this one and are read-only.

### `state.json`

Everything the UIs remember between runs, as one indented JSON object. You never need to edit it; deleting it resets these:

| Key | What it holds |
|---|---|
| `tables` | Per connection, database and table: column widths, hidden columns, filters, whether the filter bar was shown, the sort, and whether you removed the default sort. |
| `pinned` | Pinned sidebar items per connection. |
| `recent` | The **Recent** sidebar items per connection (at most 10). |
| `last_session` | The workspaces (connection and database) to reopen with `[general] reopen_workspaces`. |
| `row_limit` | The editor's row limit per connection. |
| `folds` | Folded statements per editor (saved query or connection tab). |
| `open_tabs` | Tabs to restore on reconnect (`[editor] auto_save_tabs`): SQL tabs with their text and the saved query they edit, table tabs with the table. |
| `backup_options` | The last options of the backup dialog per connection. |
| `recent_files` | SQL files you opened (`[general] recent_files` of them). |
| `connection_sort` | The sort you picked in the connection list. |
| `groups` | Your custom sidebar groups per connection. |
| `last_connected` | When each connection last connected (for `connection_sort = "recent"`). |
| `diagram_colors` | Table colours you set in the terminal ER diagram. |

Every change re-reads the file under a lock, applies the change and writes it back, so a terminal UI and a web server never lose each other's changes. Keys written by a newer version are kept.

If `state.json` is not valid JSON at start, it is renamed to `state.json.corrupt` and webtuidb starts with empty state, printing `webtuidb: <path> was not valid JSON and was moved to <path>.corrupt`. If it cannot be moved either, the start fails with `<path> is not valid JSON (…) and could not be moved aside`.

### `boards/*.toml`

Metrics boards, one TOML file each (panels of queries shown as numbers, tables or charts). A board file that does not parse is listed under its file name with the error. See [Tools](../../tools/).

### `chats/<connection>/<id>.json`

AI assistant conversations, one JSON file per chat, in a folder per connection (the folder name uses the same encoding as history files). A chat file is capped at 4 MiB: a bigger chat is not saved (`chat too large to save (over 4 MiB)`), and bigger files are skipped in the chat history list.

### `backups/`

The web UI writes backups to, and restores from, this folder only: a file name with a folder in it, `..`, a symbolic link or anything that is not a regular file is refused (`backup files live in <dir>; give a file name there`). The terminal UI asks for a path in its backup dialog instead.

### `crash.log`

If webtuidb crashes, the panic, the stack and up to the last 20 console lines are appended here, and it prints `webtuidb: crashed; details were written to <path> (nothing was sent anywhere)`. In the web server, a panic in one request or job is logged the same way and only that request fails. Once the file passes 2 MiB it is renamed to `crash.log.1` (one older generation is kept).

### `ssh.log`

The SSH tunnel debug trace when you turn it on from Open Anything in the terminal UI ({{< key "C-d p" >}}, **Enable SSH log**; the same entry then reads **Disable SSH log**). `webtuidb --ssh-log <file>` writes the same trace to a file of your choice.

## Temporary files of the web server

Exports and imports started in the browser run as background jobs and spool their data in the operating system's temp folder (`webtuidb-export-*`, `webtuidb-import-*`), not in the data folder. Per browser session:

| Limit | Value |
|---|---|
| Disk budget for import spools and finished exports | 1 GiB. Finished exports are deleted oldest first to make room; still over: `this session's temporary files are over their 1024 MB budget; download or delete finished exports and retry`. |
| Running jobs | 4 (`4 background jobs are already running on this session; wait or stop one`) |
| Finished exports waiting to be downloaded | 3 |
| Finished jobs listed in the jobs drawer | 30 |

## Locks and safe writes

- **Locks.** Files that the terminal UI and the web server may both change are written under an exclusive lock on a sibling file named `<file>.lock`: `connections.toml.lock`, `state.json.lock`, and one per history file (`history/<connection>.jsonl.lock`). On Linux and macOS this is `flock`; on Windows it is `LockFileEx` on the first byte. A second writer waits until the first is done. The `.lock` files are empty and safe to delete while webtuidb is not running.
- **Atomic writes.** `connections.toml`, `state.json` and `config.toml` (from the settings editor) are written to a temporary file in the same folder, flushed, and renamed over the old file, so a crash or a full disk leaves the old file or the new one, never a half-written one.
- **History appends** check that the file ends with a newline first, so a line cut short by a crash never swallows the next entry.
